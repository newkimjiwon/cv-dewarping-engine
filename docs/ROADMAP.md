## 1순위 — 실사 고해상도 테스트 세트 확보

지금까지의 검증은 합성 이미지 + 저해상도 실사 2장에 의존합니다. 실기기(폰 카메라 원본,
3000px+)로 아래 케이스를 모아 `inputs/`에 추가하고 결과를 눈으로 검수해야, 이후 어떤
개선이 진짜 필요한지 판단할 수 있습니다.

- 펼친 책 (휨 강/약), 낱장 문서, 영수증
- 어두운 배경 / 밝은 배경 / 문서와 비슷한 색 배경
- 그림자 진 사진, 조명 반사, 45° 이상 극단적 각도

**이걸 먼저 해야 하는 이유**: 알고리즘 개선은 이미 상당히 진행됐고, 현재 병목은
"실제 데이터에서 어디가 깨지는지 모른다"는 것입니다.

## 2순위 — 펼침면 스파인 분할 (좌/우 페이지 분리 저장)

vFlat의 핵심 기능. 책 스캔 시 실질 가치가 가장 큽니다.

- 접근: warp된 결과에서 중앙 부근의 세로 어두운 골(스파인 그림자) 또는 밝기 골짜기를
  찾아 분할선 결정 → `outputs/<이름>_left.jpg`, `<이름>_right.jpg`로 저장
- JSON에 `pages` 필드 추가
- 난이도 낮고 기존 파이프라인과 독립적이라 리스크가 적습니다.

## 3순위 — 스마트 크롭

곡면 보정 후 출력 모서리에 섞이는 페이지 밖 배경 제거.

- 접근: 경계 편차 다항식에서 각 변의 안쪽 최대 편차를 이미 알고 있으므로,
  그만큼 안쪽으로 크롭하는 옵션(`--crop=smart`) 추가. 콘텐츠 손실 위험이 있어 opt-in으로.

## 4순위 — iOS 연동 준비 (frontend/ios-app)

README의 원래 설계 의도대로 `main.cpp`만 교체하는 구조는 이미 갖춰져 있습니다.

- `detectAndWarpDocument()`를 감싸는 Objective-C++ 래퍼 (`UIImage` ↔ `cv::Mat`)
- 실시간 프리뷰용 경량 경로: 검출만 수행해 꼭짓점 오버레이 (이미 preview 해상도 검출이
  분리되어 있어 재사용 가능)
- CMake 또는 SPM/XCFramework 패키징 결정 필요

## 5순위 / 보류 — 내부 곡면 보정 고도화

경계는 반듯한데 내부만 접힌 페이지(스파인 근처 급격한 골) 대응.

- 고전 CV: 텍스트 라인 곡률 추적 (mzucker page_dewarp 방식) — 텍스트 없는 페이지에서 무력
- 딥러닝: DocUNet / DewarpNet 계열 — 모바일 배포 비용 큼
- 1순위 테스트 세트에서 실제로 문제가 되는 빈도를 확인한 뒤 착수 여부 결정
